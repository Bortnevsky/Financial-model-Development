Структура проекта:

Проект (Касаткина) состоит из очередей (1 и 2)
Каждая очередь имеет свой таймлайн (РнС, РнВ)
Есть МАСТЕР ПЛАН с вариантами распределения площадей между очередями


Площади:

Жилая: квартиры, апартаменты
Нежилая: офисы
Торговля: ритейл, ТЦ
Социалка: школа, ДОУ (места)
Паркинг: для жилья, для офисов
Loss Factor (LF) - коэффициент потерь на общие площади


Доходы:

Выручка от продаж по типам площадей
Цены: стартовая, текущая, средняя
Темп продаж по периодам
Эскалация цен


Инвестиции (затраты):

Вход (покупка площадки)
Finders Fee
Земельно-правовые: ВРИ, льготы, рассрочка
Аренда ЗУ / налог
Проектирование (К+П+РД)
Согласования
СМР: жилье, офисы, ТЦ, соц.объекты
Отделка, сети, мониторинги
Управление проектом и непредвиденные расходы


Расходы на продажу: АХР, маркетинг и реклама, брокеридж, управление продажами, регистрация договоров и аренда земли после ввода в эксплуатацию.
Финансирование: структура источников и условия привлечения капитала.

Собственный капитал (акционерное финансирование)
Бридж-кредит до получения разрешения на строительство
Проектное финансирование после разрешения
Эскроу для снижения ставки
Ставки рассчитываются как ключевая ставка плюс маржа
Комиссии за резервирование и брокеридж МРГ


Таймлайн: ключевые этапы от начала расчетов через получение разрешения на строительство, выполнение работ, ввод объекта до завершения продаж.
Результаты: доходы, расходы на продажу и инвестиции.

Интересуют проценты по кредитам, налоги (НДС и налог на прибыль), итоговая прибыль. Нужно рассчитать маржинальность до и после налогов, IRR для проекта и инвестора, NPV и LLSR.

Специфика: социальные объекты требуют расчета обязательств и зачета между девелоперами; ВРИ предполагает оценку стоимости смены разрешённого использования; чувствительность модели проверяется через таблицы к изменениям цены и стоимости строительно-монтажных работ.

```
## Шаг 3: Определяем порядок зависимостей

Некоторые расчёты зависят от других:
```
1. Площади (входные данные)
      ↓
2. Выручка = Площадь × Цена
      ↓
3. Затраты = Площадь × Себестоимость
      ↓
4. Поток = Выручка - Затраты - Проценты
      ↓
5. IRR = f(Поток)
TinyOlap/OLAP делает это автоматически — ты задаёшь правила, движок сам определяет порядок.

python# Всё что реально нужно — 200-300 строк кода

class Cube:
    """Многомерное хранилище с агрегациями"""
    
    def __init__(self, dimensions: list[Dimension]):
        self.dimensions = {d.name: d for d in dimensions}
        self.data = {}  # sparse storage: tuple(members) -> value
        self.rules = {}  # calculated members
    
    def __getitem__(self, address: tuple) -> float:
        # Если есть правило — вычисляем
        if self._has_rule(address):
            return self._calc_rule(address)
        # Если агрегат — суммируем детей
        if self._is_aggregate(address):
            return self._aggregate(address)
        # Иначе — значение из хранилища
        return self.data.get(address, 0.0)
    
    def __setitem__(self, address: tuple, value: float):
        self.data[address] = value
    
    def _aggregate(self, address) -> float:
        """Рекурсивная агрегация по иерархиям"""
        total = 0.0
        for child_address in self._expand_children(address):
            total += self[child_address]
        return total


class Dimension:
    """Измерение с иерархией"""
    
    def __init__(self, name: str):
        self.name = name
        self.members = {}  # name -> Member
        self.hierarchy = {}  # parent -> [children]
    
    def add(self, name: str, parent: str = None):
        self.members[name] = Member(name)
        if parent:
            self.hierarchy.setdefault(parent, []).append(name)
